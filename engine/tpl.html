Откуда берутся данные сейчас и как должно быть

Сейчас почти всё считается из таблиц менеджеров, потому что ключа Ozon API ещё нет, а коннектор Wildberries отдаёт только сводки. Правый столбец — целевая схема: цифры продаж тянем из API площадок, а из таблиц берём только то, чего в API нет физически — метки, расход и клики.

Короткие ссылки ozon.onelink.me раскрываются до полной, длинные читаются по параметру c=. Метка ищется по всему телу ссылки, а не только по хвосту — менеджеры размечают по-разному. ВыкупыWildberries — API, воронка продаж. Ozon — API заказов, статус «доставлен» по заказам выбранного месяца (когортно). За август 829 из 921 отправлений. Раньше бралось из выгрузки кабинета — там было 894, расхождение из-за другого способа счётаOzon: учитываются обе схемы — FBS (со своего склада) и FBO (со склада Ozon). Выкуп = отправление в статусе «доставлен»
Процент выкупаОтдельной плитки нет — убрана. Правило на будущее: считать когортно, то есть взять заказы месяца и посмотреть их финальную судьбу. Wildberries отдаёт такой процент в воронке продаж, по Ozon он собирается из отчёта по заказам: доставленные отправления ÷ все отправления месяца. Август — 829 из 921, то есть 90%, совпадает с кабинетом. Аналитику воронки Ozon (ozon_analytics) использовать нельзя: там выкупы по дате доставки, а заказы по дате заказа, и процент выходит вдвое ниже реальногоНа незакрытом месяце цифра не готова: заказы первых чисел доставлены на 85%, последних — на 10%. План суммы заказовОтдельной строки под сумму заказов в медиаплане нет. Берём строку «Выручка план, ₽» — она считается как заказы × средний чек × % выкупа, то есть по смыслу это плановая сумма до выкупа. Один и тот же план стоит и на плитке «Сумма заказов», и на плитке «Выручка»Завести в медиаплане отдельные строки: план суммы заказов (до выкупа) и план выручки (после выкупа). Тогда две плитки перестанут делить одну цифру
ВыручкаWildberries — API: сумма выкупленных товаров, а не «к выплате». Средний чек выкупа считается как сумма выкупов ÷ количество выкупов. Ozon — выкупы × чек из выгрузки. Авито — сумма выкупленных заказов (delivered + closed). Комиссии площадок нигде не вычитаютсяOzon тоже на API, по той же логике — сумма выкупленного, не к выплате

Метки: артикул, промокод, UTMТаблицы менеджеров по инфлюенсу. Подменный артикул WB берётся из колонки «Подменный артикул», а если она пустая — из поисковой ссылки WB (search=WW…) в колонке «Ссылка с UTM». Заказы по подменным артикулам WB — только из таблицы менеджера: в API Wildberries этих данных нет вообще, они есть лишь в кабинете («Рост продаж → Подменные артикулы»). Заказы по UTM Ozon — из API Ozon «Внешний трафик» (коннектор ozon_utm: разрезы campaign, content, term; заказы в окне атрибуции), обновляется при каждом обновлении данных по API. Сентябрь — отчёт Ozon от 21.09, август — выгрузка кабинета от 17.09. Как сопоставляем: короткие ссылки onelink.me раскрываются полностью (все 42 раскрыты на 21.09); метка ищется по всей ссылке. Если у метки одна кампания на одно размещение — сопоставляем по кампании. Если одна кампания стоит на нескольких размещениях — различаем по хвосту ссылки: utm_content, затем utm_term, затем utm_source. Заказы кампании, которые не разошлись по хвостам, делятся поровну между её публикациями без своего совпадения (например, 2 заказа vendor_org_4202727_max_m1 из 14 — публикации «Охота / Рыбалка / Отдых»). Если заказ по метке пришёл в месяце, где публикации с этой меткой нет, он засчитывается публикации прошлого месяца отдельной строкой «заказы по метке публикации от …» — в тот месяц, когда случился заказ, без расхода. На сентябрь по меткам сопоставлено 245 из 249 заказов (4 заказа — метка собственного бота, не публикация). Пороги CPO по продуктамРазный средний чек — разные пороги. AMINOTRIGGERFISH (Сигнал и Прикормка): зелёный до 200 ₽, жёлтый 200–400 ₽, красный выше 400 ₽. Аппликатор Ермакова: зелёный до 800 ₽, жёлтый 801–2000 ₽, красный выше 2000 ₽. Боты — CPA: зелёный до 130 ₽, жёлтый 130–250 ₽, красный выше. При фильтре «Все продукты» в таблицах действуют пороги AMINOTRIGGERFISH, а в блоках «Лучшие» и «Слив бюджета» каждая строка красится по своему продуктуПороги задаются вручную. Правильнее считать их от юнит-экономики: целевой CPO = маржа × допустимая доля рекламы, по каждому продукту отдельно
Заказы и регистрацииДве независимые метрики, никогда не складываются. Заказы и CPO — у товаров, регистрации и CPA — у ботов. Сквозные метрики, которые суммируются по всему: бюджет, размещения, кликиКогда бот начнёт приводить продажи, заказы из бота встанут в товарный контур с активностью «бот» и своей площадкой (WB, Ozon или сайт)
Органика в планеМедиаплан построен от бюджета: заказы = бюджет ÷ целевой CPO. У органики бюджета нет, поэтому строки в плане нет, а плановое «Итого заказов» — это только платные каналы. В блоке «План месяца» факт считается по тем же данным, что и плитки: органика входит в факт продукта и в итог, в разрезе активностей — отдельной строкой без плана. Поэтому итоги блока и плиток совпадаютТак и оставить: органика — это результат, а не статья бюджета. Её можно скрыть фильтром «Органика» — тогда она уйдёт и из плиток, и из блока плана
Площадка продаж, когда колонка пустаяЕсли «Канал продаж» у менеджера не заполнен, площадка определяется по метке: артикул на WW — Wildberries, ссылка с ozon — Ozon, ссылка на trigger-fish — сайт. «Не указано» остаётся, только если нет ни одной зацепкиОбязательное поле «Канал продаж» у всех менеджеров
План — весьТолько общий медиаплан «Медиаплан_Маркетинг», лист «План упрощённый»: бюджет, заказы, выручка, продукты и каналы. Из этого файла берётся только план — колонки «факт» после каждого месяца не читаются вообще (факт там вносится вручную и может расходиться с площадками). Плановый бюджет месяца — это сумма строк «Итого бюджет» по продуктам выбранного среза, она совпадает со строкой «ИТОГО БЮДЖЕТ» в своде; строку «Плановый бюджет» из блока контроля дашборд не использует — это годовая прикидка. С 01.10.2026 в файле два аминотриггера: «Сигнал» (то, что продаётся) и «Прикормка» (сухая, ещё не запущена — есть план, факта нет). Медиапланы в таблицах менеджеров как источник плана не используются — они не сходятся с общим (август: 34 034 заказа против 13 205 в сумме у менеджеров)Тот же файл, но с разбивкой плана по менеджерам на каждый месяц — сейчас такой блок есть только под один выбранный месяц

Фильтры: когда сбрасываютсяФильтр откатывается на «все», если выбранное значение не встречается в текущем срезе — иначе экран был бы пустым. Например, выбрана площадка «Авито», а потом активность «Инфлюенс-посев»: посева на Авито нет, площадка сбросится. Исключение — продукт и активность, у которых есть план: они остаются выбранными даже без факта, чтобы можно было смотреть план по ещё не запущенному продукту. Так работает AMINOTRIGGERFISH Прикормка: в октябре у неё есть план и нет факта, и фильтр её держит; в сентябре плана нет, поэтому её нет и в спискеТак и оставить: сброс защищает от пустого экрана, а план-без-факта виден там, где он задан
Статус источниковРядом с датой обновления показано, сколько процентов выбранного месяца прошло — это ориентир к проценту выполнения плана: если прошло 80% месяца, а план выполнен на 60%, темп отстаёт. Для прошлых месяцев всегда 100%. В шапке под датой обновления — раскрывающийся список: когда последний раз обновлялся каждый источник. Дата берётся из времени файла с данными, поэтому её нельзя забыть проставить. Цвет: зелёный — свежее, жёлтый — пора обновить, красный — устарело. Для API нормой считаются сутки, для таблиц менеджеров и выгрузки Тильды — трое суток, для медиаплана — месяцАвтообновление раз в сутки — тогда у API всегда будет зелёный
